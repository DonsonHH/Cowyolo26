# 12事件的流式读码关联与真实身份查询：异常和压力验证

2026年10月29日。**已把流式RF入口接到现有12事件照片与真实CPU身份进程，完成10个功能条件、2个压力控制、144条台账和515次实际身份配置查询。** 迟到不会倒填早先决定，同码重传不会增加事件，共享视觉窗口保持歧义，容量拒绝和过期都有明确终态。

这是合成读码／真实模型查询的软件实验。它使用同一段12事件的实际时间与照片，不能写成144头独立奶牛、现场RF数据或板上性能。原片人工总数12头的计数成果、照片、模型和拒识阈值保持不变；两个公开匿名身份候选020／009仍未独立核实。

## 1 本轮解决的是哪个衔接问题

早期[RF规则与队列实验](<../rf_queue_20261026/受控耳标与队列实验.md>)使用构造通行和已缓存的视觉分数；[上一轮12事件链路](<../confirmed12_capture_identity_20261029/12事件原图抓拍与身份查询结果.md>)则只有显式模拟缺码分支。本轮保留这两部分既有成果，把实际源事件时间、当前可见视觉窗口与真实身份前向接起来。

关键是**一个完整计数事件已经出现，不代表旁边没有尚未完成的通行**。若读码同时符合它与邻轨迹的时间窗口，就不能因邻轨迹还未跨完计数门线，提前把该码叫作唯一关联。

本轮沿用旧Resolver的码值去重、共享检查、登记表查询和迟到规则，只增加流式视觉窗口适配。当前ROI观察的中心进入y=0.25–0.75时建立候选窗口，包含待确认观察；完整计数事件出现时关闭。没有形成完整事件的轨迹，在50源帧未见后按最后观察时刻结束窗口，不产生新的计数事件，但保留其历史歧义。回程再入中区可建立新窗口。

RF决定在事件关闭后15源帧作出，捕获时间必须落在该候选窗口内，收到时间必须不晚于截止，读区一致且记录有效。该规则是预声明的模拟几何／统一源帧时钟合同，尚未由真实天线覆盖与传感器时钟验证。

## 4 为什么“每事件一个码”仍有7次共享歧义

S01的码按构造所属事件分别生成，但运行组件看不到这个所属标签，只看到捕获／接收时刻、读区、码值和当前视觉窗口。25个软件视觉窗口中只有12个最终形成计数事件，其余13个也会参与可见歧义检查；25不是实际奶牛数。

以E007为例：

| 当时可用的证据 | 源帧 |
| --- | ---: |
| 轨迹96候选窗口开启 | 9385 |
| 邻轨迹98候选窗口开启 | 9395 |
| 注入的SIM-TAG-007捕获并收到 | 9460 |
| E007完整计数事件关闭 | 9465 |
| E007 RF截止 | 9480 |

在9480帧，轨迹98仍可见且没有形成完整计数，它的窗口仍开着。9460帧的读码同时符合轨迹96和98两个窗口，所以结果为共享，触发视觉查询。事后它在9690帧形成E009，只用于解释记录，**未来的E009信息没有提前给关联器**。

这体现保留歧义的代价：S01只跳过5个事件的身份查询，即相对S00少25次配置前向；不是证明已正确绑定5头牛，也不是实测节能。当前视觉窗口不是实际天线读区，真实位置、覆盖及同步数据到位后应按实际证据定义关联合同，而不能为了提高“唯一候选率”缩窄窗口。

## 5 本轮保留的两个重要局限

**唯一有效码仍可能属于别的牛。** S07故意把每个事件的码换成另一条已登记模拟码；5个无共享歧义的事件仍输出对应错误模拟登记项。这个控制表明规则无法仅凭唯一性发现单码错误。它不是实测5次牛只错配，SIM命名空间也不与公开匿名020／009合并；所有结果保持候选，未自动写正式身份或牛只档案。

**时钟检查不等于传感器同步。** S06筛掉无效标记、其他读区以及接收早于捕获的记录；真实RF与相机时钟都内部自洽但彼此偏移的情况，仍需同步与校准数据验证。本轮的统一源帧时钟、截止15帧、50帧未见政策都是声明过的实验条件。

迟到条件中，12个独立读码记录形成13条事件关联证据，其中一条可以与多窗口有关系；不能写成13头牛或13次独立RF故障。部分“对所属事件迟到”的读码对另一窗口可能仍及时，但共享检查仍保留歧义。已输出的候选／无候选决定不因后来收到读码或窗口关闭而倒改。

## 7 接下来继续科研的顺序

1. **优先查可公开复核的身份来源对应。** 核对原视频、作者裁剪和匿名ID之间能否建立可靠的来源链；若仅有相似花纹或模型高分，仍保持候选。来源或独立复核到位后，才能做真正的事件级身份评价，当前原片人工12头总数验收继续保留。
2. **在有标签身份数据上固定裁剪域实验。** 研究完整身体、邻牛边缘与朝向处理，对照完整图库检索和未知拒识，保持训练／阈值验证／新评价的角色分开；不根据020／009两个已见候选选阈值或模型。
3. **将RF关联要求带到实际系统。** 需要同步RF采集、天线覆盖及单码错误的额外核对依据。当前代码给出了逐观察入口、共享歧义和终态接口；“读到唯一合法码”仍是需要验证的身份候选条件。
4. **继续单板部署关口。** 当前真实CPU查询和受控屏障没有验证PYNQ共享资源。板卡信息到位后，以具体单模型运行路径验证导出数值、算子、内存和最长不可抢占段，再测前台检测／后台身份联合会话的队列、丢帧与能量。两个推理任务最终都在PYNQ-Z2。

科研材料中本轮适合作为异常输入与失败状态的可复现系统实验。实际身份效果、真实双向覆盖和板上联合运行继续按各自证据验收，不能把软件规则通过写成整项课题或论文已完成。
