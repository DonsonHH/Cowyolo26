# 奶牛数据审计与服务器开发基线

本目录保存2026年10月26日的数据审计、服务器下载/传输证据、清洗代码和YOLO26n开发基线。研究目标保留公开数据优先、最终检测和身份推理均在PYNQ-Z2上完成；本轮GPU结果属于服务器开发结果。

从[数据集审计与基线进展](<数据集审计与基线进展.md>)开始阅读。`local_opencows`保存完整本地审计与图像检查，`server_results`保存取回的元数据、模型记录与回放检查材料，`tools`保存实际运行代码。

服务器项目：`/share/home/renly/projects/idcoo_research_20261026`。原始数据在`data`，模型与权重在`models`和`results/detection_pilot`，计算作业日志在`logs`。

## 1 已执行的流程

1. 使用已校验主机密钥的SSH核对账户、主机、HOME、实时分区、队列与磁盘。
2. 读取本地OpenCows2020归档全部成员，检查图像、标签、重复、分辨率和来源分层。
3. 将完整归档传入服务器并在Slurm中核对SHA256及解包；另外直接在服务器取得Cows2021和MultiCam原视频样本。
4. 原始标签保留，另外生成边界裁剪后的检测标签与开发划分。
5. 完成GPU可用性和YOLO26n推理检查，运行官方权重计数开发基线。
6. 用OpenCows派生集完成5 epoch微调，再以相同视频和计数规则回放比较。

详细作业状态、产物与本轮局限以阶段报告和取回的最终证据为准。程序的A/B方向是相机区域方向，不能直接改写成牧场进出方向；预测事件数没有独立真值时不能当作准确率。

## 2 如何复现

先使用use-renly-slurm技能确认当前远程身份、拓扑、队列和离线输入。以下是本轮采用的项目路径，实际分区及GPU资源需要当次再次确认。

```bash
cd /share/home/renly/projects/idcoo_research_20261026
sbatch tools/prepare_clean.slurm
sbatch tools/train_detection_pilot.slurm
sbatch tools/replay_finetuned.slurm
```

顺序依赖：清洗作业完成后检查清洗摘要，再训练；训练作业终态成功、日志和checkpoint有效后，才执行回放。训练脚本默认输出`five_epoch_dev`，重跑时应指定新的运行名称，保留已有结果，不能将重复作业的文件混在一起。

训练预算是5 epochs、320输入、batch 32、seed 26。原始模型、训练后模型、输入数据清单和源代码都应保留哈希。官方权重与微调权重采用不同输出目录；开发验证成绩不能替代跨会话/农场的最终验证。

## 3 数据与代理边界

完整OpenCows归档已校验。Cows2021与MultiCam采用明确记录来源和哈希的样本子集，本轮没有取得它们的全部数据。下载未完成的`.partial`文件不能作为可用输入。

直连小文件成功，大文件限时传输失败或速度不足后，按用户授权使用独立回环端口和普通US3节点。没有修改既有节点选择；订阅和含凭据配置仅通过进程内输入/内存传递，不写入项目或结果包。最终工具清单与结果不包含私人订阅地址。

## 4 下一阶段

根据本轮原视频审计确定计数开发场景，新增未使用的视频留出集并完成通行真值，检查反向与同时对向通行条件。随后独立建立花纹图库/查询划分、未知拒识与轻量身份编码器，最后进行Z2工具链、量化映射和双任务联合验收。

本目录不包含PYNQ-Z2上板成功、身份找回准确率或现场RF协同效果的声明。
