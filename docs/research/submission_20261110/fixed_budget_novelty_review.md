# 固定检测调用预算下的通行计数：近邻方法与贡献边界

核查日期：2026-11-10。范围：第一手论文、作者代码入口，以及本项目已完成的一个开发对照。本轮仅写本文件；没有登录服务器、运行模型、下载数据集、修改实验或访问 USB／串口／JTAG。本文是有边界的近邻核查，不能当作覆盖全部文献的系统综述。

## 1. 可以继续研究，但贡献需要落在具体的资源分配问题

**“低分辨率粗检后，再选择局部放大识别”已经是既有方法；“根据视频内容自适应分配计算”和“等待较新帧以改善实时感知”也已有研究。** 因此，YOLO26n 的版本、PYNQ-Z2 部署成功、局部抓拍或条件计算本身，都不足以单独构成新颖性。下列六篇分别覆盖局部放大、尺度选择、实时调度、边缘决策和牛只通行任务。

本项目目前更具体的问题是：**同一静态检测图、同一输入尺寸、同一真实调用配额下，第二个调用应观察新的全局图，还是核验上一张图的局部区域？** 后者可能补足某次完整通行的实际观测证据，却同时放弃一次较新的全局观测，并延后该旧图结果的发布时间。研究价值取决于这种交换能否在冻结的多个视频中带来可复核的计数收益，以及收益的时间代价。

这是对本项目的研究判断，不是上述论文已经证明的结论，也不是首次性声明。

## 3. “等真实调用预算”具体排除了什么，还没排除什么

本项目已核验的开发对照见 [DEV_PAIR_VERIFIED_V1.json](C:/Users/Donson/Documents/ChatGPT/奶牛/submission_readiness_20261110/DEV_PAIR_VERIFIED_V1.json)。每组有 300 次非热身真实图调用，另有 1 次单列的热身；A 是 300 次全局，B 是 287 次全局＋13 次局部。已曝光 Aug20 片人工参考为 12，A 计9、B计12；对应绝对误差为3、0。B 的最大事件发布时间年龄约849.2 ms，A约438.9 ms。600个真实原始输出已由主流程校验。

这些数据支持的是“一次开发片的相同调用配额比较”，不支持“所有视频都更准”“恢复了恰好3次漏计”“事件零漏计”或统计显著性。总数吻合可同时包含相互抵消的漏计与重计；需要按实际可得参考，只报告方向总数误差。V2 时延字段的测量边界按该 JSON 的说明解释；不能把包含日志开销的字段当成纯 FPGA 核延迟。

| 对公平性的控制 | 当前可解释的范围 | 仍需保留的测量／说明 |
|---|---|---|
| 同一个模型图、同样输入尺寸、相同非热身调用数 | 排除“B只是比A多做了若干完整检测”这一主要混淆 | 调用账本与真实 raw 绑定；热身、启动和失败尝试分别列出。 |
| 第二槽明确在“新全局图／旧图局部”间替换 | 把新鲜度与细节的取舍具体化 | B 少看了哪些全局源时刻，以及局部核验使用哪一张实际图；不能补读未来帧。 |
| 同一套关联、几何与计数配置 | 减少不同跟踪／门线参数带来的混淆 | 相同名义 tracker 时钟，实际源 PTS 驱动间隔；同图全局／局部合并后只更新一次。 |
| 相同静态图的实际调用预算 | 更接近约束住主要神经网络工作量 | 这不等于完全相同的 CPU 时间、端到端耗时、功耗或能量。提案、裁剪、融合、跟踪与日志开销仍应实测。 |
| 多次按原时序板端回放 | 可检查调度、采集与计时波动 | 重复同一片不增加独立视频或动物数。平衡 A/B 顺序并保留失败，可减少顺序／热状态影响，但不能凭此证明泛化。 |

这是本项目的对照设计解释。既有文献并非都采用“相同神经调用次数”；例如 AutoFocus 的像素量、AdaScale 的动态尺寸或 Chanakya 的混合配置，均使每次调用的成本不同。不能将本协议称为唯一正确的公平性定义。它适合当前固定图架构，但还需要同时报告实际端到端时间。

## 4. 当前最窄的贡献表述

可先采用以下**待完整结果验证**的论证骨架：

> 在固定检测图和真实调用配额下，研究新的全局观测与既有图局部核验之间的分配。以奶牛完整通行计数为下游目标，使用实际观测约束事件，并在 PYNQ-Z2 上按源时间回放，联合报告视频方向总数误差、实际调用与发布年龄。

若全部预定结果支持，可以把贡献写为三项：

1. 一个明确的任务设定：固定模型、有限实际调用预算下的“时间覆盖／空间核验”交换，而非将更大模型、更多调用或更高分辨率同时引入。
2. 一个可复现的因果分配与同图融合实现；局部提案依赖当前及历史实测，预测位置不充当通行证据。
3. 一组真实板端的配对比较，证明在报告的场景中收益与代价分别是什么，并公开全部冻结条件、失败和原始调用证据。

这些贡献属于**任务导向的系统设计与实证**。现在没有充分依据将其称为新的目标检测网络、通用调度理论、新硬件架构或身份找回方法。临时 track ID 也不等于具体奶牛的长期身份。

等预算比较用于隔离分配策略，尚不能证明所选配额是本板卡的最佳工作点，也不能证明B优于所有可实时运行的全局检测配置。主文应交代配额的预先选定理由；若没有在多个预算点和可行基线上的完整比较，就不写“最优”“Pareto最优”或“达到最大吞吐”。这是解释当前结果所需的边界，不建议在已开始的冻结批次内临时换配额。

英文候选题名可用：

> *Allocating a Fixed Detection Budget Between Global Observations and Local Verification for Embedded Cattle Passage Counting*

题名是否使用“improving”“accurate”等结果性词汇，应等所有冻结评价结束后决定。

## 5. 后续结果如何决定 GO／NO-GO

以下是科学判断门槛，不是期刊硬性条款，也不要求用户制作事件 JSON。

- **若多个冻结视频的配对误差改善稳定，且发布年龄的代价可接受**：继续按上述窄贡献写稿。逐片报告参考数、两种预测、绝对误差和调用分配；不要只给全部视频累计总数。新会话的参考可由用户只确认完整上行／下行总数。
- **若只在这一已调试片改善，其他片无益或明显退化**：不能写成已验证通用策略。保留为开发发现，分析触发与场景条件；现有结果更适合作为工程验证／研究短稿的起点。这里不是要求新增更多数据集，而是先完整报告已冻结的所有结果。
- **若总数对了但模型调用或帧可得性不满足协议**：不能将该轮算作合格的等预算比较。保留失败证据，区分算法计数与执行合规性。
- **若B的收益可由一条更简单规则同样获得**：当前复杂触发机制的额外贡献不成立。可以使用已记录的同一真实输出流做不反馈调度的 use／mask 影子回放，检验局部测量是否必要；影子运行不是新的正常运行时延成绩。
- **若没有未参与选择的会话结果**：可以有开发可行性结论，但不宜将稿件整体表述为已经完成独立泛化验证。四片重放多次仍是四片；同牧场的新日期／相机亦不等于跨牧场泛化。
- **若主要卖点仍是新型号YOLO移植、累计数量碰巧一致或名义FPS**：对以新颖性为要求的正式研究论文应判当前证据 NO-GO，先改论证和验证；不能以增加篇幅或隐藏失败补足。
