# 独立计数参考候选核查

2026年10月27日。为补充现有单片6事件诊断，本轮核查了新的通道计数和轨迹资源。**尚未取得新的合格双向通行测试集。** 本轮没有对这些素材运行模型，也没有改变已固定的Cows2021训练协议。

## 1. CattleEyeView：通道与折返更贴题，实际数据仍待取得

作者论文介绍了俯视装载通道视频，包含跟踪ID和通过区域的计数，且说明折返会造成重复计数；数据由人工标注并复核。它因此是值得优先核查的外部计数候选。[作者论文III–IV节](https://arxiv.org/html/2312.08764v1)

作者仓库的“Dataset and Codes”链接目前指向[Google表单](https://forms.gle/KGf3dmEjPX9qwVz49)，仓库本身未提供可直接读取的标注文件。本轮只检查公开入口，表单请求超时，内容与具体要求未成功读取，未填写或提交，也没有取得数据。因此不能从论文说明推断所需片段已经在本地、包含合格双向通行，或已经完成许可准入。[作者仓库](https://github.com/AnimalEyeQ/CattleEyeView)、[入口实查](<../../../research/counting_reference_candidates_20261027/evidence/CattleEyeView_form_route_check.json>)

后续若取得数据，还要先区分计数对象：本项目分别记录方向性通行，同一头牛完整出去再回来是两个方向事件；论文中的通过动物总数是否采用同一去重规则，需要读取实际标注和评价代码。不能直接把一个动物总数当成本项目双向事件真值。需要由轨迹和固定区域定义重新导出事件，并核查折返/截断，不根据模型预测选择参考。

## 2. MooTrack360：实际取得了轨迹包，发现时间对齐风险

Zenodo公开记录提供`TrackEval_evaluation_code.zip`，目录预览列出单独GT和序列配置。本轮实际取得23,441,568字节，MD5与发布页一致，SHA256为`26800ea3b6e653e4e9d7c54a2587060bd2a920b4e862f0b84afef624234b6478`。只解析数据文本，没有运行包内作者代码，也没有读取已发表跟踪器输出作为真值。[官方记录](https://zenodo.org/records/20287681)、[包获取证据](<../../../research/counting_reference_candidates_20261027/catalog/MooTrack360_TrackEval_evaluation_code.record.json>)

由实际GT逐行计算：350272行、8个轨迹ID，帧1至53920都有标注，框尺寸为正且位于2944×2944图像范围内，没有重复的帧/轨迹ID组合。十列中的末三列全部为-1，当前保持未解释，不擅自当作类别或可见率。[完整标注审计](<../../../research/counting_reference_candidates_20261027/results/MooTrack360_annotation_audit.json>)

序列配置与官方同名视频的容器信息存在差异：

| 项目 | 包内seqinfo.ini | 视频MP4容器实际元数据 |
| --- | --- | --- |
| 帧数/样本数 | 53920 | 53946 |
| 帧率 | 10 | 约14.985014985，即30000/2002 |
| 由本列推算的时长 | 5392秒，约89.9分钟 | 3599.9964秒，约60分钟 |
| 分辨率 | 2944×2944 | 2944×2944 |

视频检查只用HTTP Range读取顶部box头和`moov`目录，共约1.08MB，没有读取`mdat`图像载荷或解码帧。解析器先在已有演示MP4上与ffprobe核对，尺寸、帧数、帧率和时长一致。[容器实查](<../../../research/counting_reference_candidates_20261027/results/MooTrack360_container_probe/summary.json>)、[解析器控制](<../../../research/counting_reference_candidates_20261027/results/container_parser_control.json>)

这个结果确认了需要解决的时间信息差异，但没有证明GT应如何映射到视频。不能只把10改成14.985就宣布对齐，26帧长度差还需判断是末尾截断、原片版本差异还是其他处理。视频文件名中的“annotated”也需要检查是否含烧录标注，以及能否取得同源干净输入。

## 3. 当前选择与后续准入

两项都保留为候选，不加入本轮训练或报告新计数准确率。CattleEyeView优先核查实际数据访问和事件口径；MooTrack360优先核对同源原片、帧索引和时间，再检查鱼眼牛舍画面是否存在可解释的完整通行区域。牛舍内任意运动跨线，不能自动当作真实牧场出入口。

后续独立评价的顺序仍是：确认来源与使用条件 → 选定会话和校准片段 → 固定区域、事件与截断规则 → 冻结参考 → 所有待比较模型一起冻结 → 预测和逐事件评分。图像/参考可用性与模型质量分开验收。用户安排的原片独立人工JSON继续保留为另一条参考来源。

本轮完成的是新候选的实际格式审计与风险发现，没有替代人工复核、没有获得真实RF读数，也没有完成PYNQ-Z2性能验证。
