# 轨迹确认前入口观察交接：计划与验收

2026年10月28日。承接[确认延迟状态诊断](<../tracker_clock_20261028/跟踪时钟与稳定区间诊断.md>)。目标是在固定检测／跟踪输出下验证一个具体交接改动；本轮不根据粗略总数选参数。

## 规则与范围

只保留同一临时ID紧邻确认前的一次ROI观察。确认成功时，将该观察交给此ID独立的原计数器，再处理当前已确认观察；未确认、确认失败或不相邻的观察不发布事件。反复未确认只替换一个暂存项，不累计稳定样本。

每ID使用同一个已冻结`ZoneCounter`实现；关闭历史交接时必须与原全局计数器事件完全相同。使用独立ID时钟是为了接回历史时不倒退其他ID的时间。事件时间只取当前已确认观察，不追溯发布。区域0.4／0.6、稳定3次、最大间隔2秒、ROI和ByteTrack参数保持原值，规则对A→B和B→A对称。

源片仍从帧0开始处理，只评价／展示8912–10873。三个Cows2021末轮checkpoint、原生检测框、安装源码与计数器副本均绑定SHA。暂存空间每ID只一条观察；这不是整个系统内存或板上性能证明。

## 执行与准入

1. 原计数器在抽象但同机制的启动延迟用例中应不能计数。实际红灯已记录：正向及反向两项失败，其余10项通过，2项新接口校验跳过。
2. 新模块通过14项行为检查，包括确认失败、间断、长间隔、首次在B区、无暂存时两次A仍不足、多ID事件顺序及不重复发布同一时刻事件。原失败日志保留；模块变动后继续检查。
3. 三个固定模型重放时，原轨迹、历史及原11／10／11事件必须精确一致；关闭交接的新封装也必须精确一致。之后比较开启交接的新增、消失和时间变化。
4. 逐帧记录确认集合、已确认位置、待确认位置及历史接收决策，用另一实现独立复算三条计数路径，核对因果时间和每ID一次接收。
5. 核验Slurm终态、文件SHA和媒体；新增预测回到源图核查。独立事件JSON到位后再计算准确率，新会话及真实双向覆盖继续补齐。
