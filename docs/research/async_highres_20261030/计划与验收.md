# 有界高分辨率输入与真实同板并行：事前计划

2026年10月30日。上一阶段为实质进展：256读取条件和138真实前向支持存储等待解释，否决仅靠readinto的优化。本轮推进完整流水线；原人工12、模型／跟踪／计数／图库／阈值均保持。

1. 固定同一mosaic050_seed26、192、O8、1秒几何抓拍选择、PNG0与空闲ARM身份后台。比较serial_input和async_input，四次顺序为serial→async→async→serial，每次392个5Hz时隙、78.4秒。两轮设备重复不是跨会话验证。
2. 仅改变高分JPEG读取和校验的调度：serial由前台在模型后执行；async由同一父进程的线程在该帧全局释放后读取，并与前台模型计算重叠。前台必须取得当帧已发布JPEG后才继续选择／入队，等待纳入释放至计数。两组都对当次取得的JPEG算SHA；与上一轮串行相比新增完整校验成本，故本轮串行才是直接基线。
3. 生产者不提前读未来帧，不预先把260MB JPEG全部放进内存。异步源每个释放时隙都读，包含前台跳过的源帧；串行只读实际处理帧。固定此实际输入策略差异，不把它写成严格同一读取次数的消融。低分192输入仍为已就绪回放，不是相机曝光／双流接收证明。
4. 生产者保留最新6帧及一个当前请求的旧帧，清理后最多7份JPEG；新读取瞬间可能第8份。前台原选择环清理后6帧、读入瞬间7；队列可另外持有选中的JPEG副本。分别记录负载、瞬时峰值与进程内存，不称全部系统内存仅几MB。
5. 先通过生产者释放时间、过期淘汰、慢消费者固定、错误传播和停止的行为验证，再冻结载荷和运行。异步生产者的pin不阻塞模型，获取数据时才等待；记录实际线程读取／校验／发布及前台等待，不依据未来的检索分数选择照片。
6. 四次均从同模型真实0–8910 raw恢复1783前史，每次2预热、启动前共8实际视频锚点。所有实际O8输出对既有完整实机raw精确检查，所有计数路径、JPEG来源、照片／张量／特征／检索及后台进程终态独立复核。数量与迟到若退步照实保留；身份无永久GT，不把更多接受预测当正确。
7. 对比实际吞吐、跳帧、P95／P99、超过200ms数量、后台等待和计数波动。采用需要完整结果，不能因较窄微基准或最好一轮通过就全局替换。输出Markdown、全部照片和自审；线程及子进程全部退出、原O8与服务核查后结束设备分支。
