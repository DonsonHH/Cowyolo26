# Lost轨迹的低分恢复：单因素计划

2026年10月28日。承接[第二阶段纯IoU结果](<../secondstage_iou_20261028/第二阶段代价对照与结果.md>)，当前主计数预测为12／11／11。该轮恢复低分匹配却未增加事件，因此本轮单独检查Lost轨迹在第二阶段的资格。

唯一变化是候选池从`state == Tracked`改为`state in (Tracked, Lost)`。只使用原跟踪器保留池中尚未移除的ID及实际低分检测；IoU代价、0.5门槛、第一阶段分数融合和0.8门槛、30次更新保留参数、检测阈值、ROI、确认前观察交接和三次稳定规则不变。不改变全局参数，不让低分框建立新ID，也不把预测框作为新观测交给计数器。

## 固定顺序

1. 用实际跟踪器对象复现Lost后的单目标／双目标低分恢复失败。原12项测试中应只有这两项失败，其余9项通过、候选范围检查跳过；红灯作为预期故障记录。
2. 通过候选12项行为检查，包括低分不建ID、低IoU／不重叠不恢复、过期ID不复活、第一阶段优先、一个低分框不能同时恢复两ID。AST核对只修改资格表达式，其余第二阶段与第一阶段方法不变。
3. 对三个固定模型缓存分别运行“纯IoU且只接收Tracked”与“纯IoU且允许Lost”，共六条件。原三组须精确复现此前全部轨迹／历史、两类事件及全画面跟踪输出；主计数仍是同一确认交接，另保留仅确认观察的诊断计数。
4. 保存所有非空第二阶段代价、资格、实际配对、匹配前状态与距上次观测的源帧间隔；独立复算六条件×两计数器的12条路径及代价，保留所有seed／不利结果。
5. 若事件或轨迹发生变化，核查源图并制作8912–10873的同步回放；收到人工JSON后按冻结协议统一评分，不按“十几头”的粗略数调参。

## 风险和解释

Lost预测位置可能靠近另一头并排奶牛，允许更多候选可能抢走原本属于活动轨迹的框。这是需要验证的候选资格扩展，不能仅凭恢复次数或更多事件说正确率提高。当前不新增年龄／运动门槛，避免把多个因素混在一起；既有保留参数和过期清理时点保持原实现。

源片已反复用于开发；本轮真实对象短序列不是新现场数据。独立人工JSON、新会话与真实双向、PYNQ-Z2联合运行继续按总目标保留。板卡信息由用户稍后提供。
