# 受控耳标关联与后台队列实验

2026年10月26日。承接已冻结的5套身份候选输出，本轮实现可复用的观察关联逻辑，并验证后台任务的预算和未解决状态。**完成的是软件规则及代价敏感性实验，板上性能仍待测量。**

## 1 输入与规则

视觉候选来自上一轮A、B及三个训练seed，身份、相似度和拒识阈值保持不变。将60张已评价的裁剪查询映射为60个构造事件，另生成正常、缺失、同码重复、延迟、多码冲突、唯一错码及图像/事件缺失输入。事件时间和方向是构造参数，不是这些原图的真实通行标注。

运行组件只接收不透明事件/图像编号、可观察RF原始记录、码值登记表和视觉候选，不接收期望身份或已知/未知真值字段。真值只在输入扰动生成和最终评分中使用。RF正常输入的正确码是按真值生成的理想正对照，不能将其成绩当成真实牧场RF准确率。

关联使用同一模拟读区及统一时钟：通行前后1tick的捕获窗口，通行关闭后等待5tick。代码先在窗口内同码去重，再检查单码、读区和读数到事件的一对一关系；共享同一读数的重叠窗口保持疑难。超过截止时间才收到的读码保留为迟到证据，不倒填早先决策。

唯一RF候选没有身份正确保证。RF异常时才调用视觉候选；视觉拒识、无图、超时、容量不足和会话结束未完成均保留未解决原因。每个构造事件保持`N=C+W+U+M`，额外事件另列。

## 2 耳标受控结果

在全部读码缺失时，60个构造事件的结果如下。30个对应图库内身份，另30个对应图库外身份；后者视觉拒识计入U。

| 冻结视觉条件 | 正确身份C | 错误身份W | 未解决U | 缺失事件M |
| --- | --- | --- | --- | --- |
| A 官方中心裁剪/冻结编码器 | 11 | 0 | 49 | 0 |
| B 全躯干填充/冻结编码器 | 9 | 0 | 51 | 0 |
| C 训练seed26 | 23 | 2 | 35 | 0 |
| C 训练seed27 | 14 | 3 | 43 | 0 |
| C 训练seed28 | 17 | 0 | 43 | 0 |

seed26的两个W分别来自一次登记牛错配和一次图库外误接收。这些分数沿用上一轮实际视觉输出，本轮没有重新选阈值。对比不是新独立识别测试，而是把已有候选接入状态和分母。

| 扰动 | 实际结果及解释 |
| --- | --- |
| 理想正常读码 | C60；正确码按真值构造，用于验证规则接线 |
| 每个码再重复两次 | 仍C60，没有将重复读数变成更多通行 |
| 全部读码缺失 | 按上表视觉回退，未知或证据不足保持U |
| 全部读码迟到 | 截止时按视觉回退，与缺失表相同；迟到读码另存 |
| 每个窗口出现两个不同码 | 保留冲突后视觉回退，与缺失表相同 |
| 每个窗口仅有一个有效但错误的码 | W60；当前规则不会仅凭唯一性发现此类错误，且不会触发视觉核对 |
| 读码缺失且无快照 | U60；事件已观察到，因此不是M |
| 每5个构造事件移除一个视觉事件 | C48、M12；这是预设漏事件敏感性控制，不是实测20%漏检率 |

当前原型揭示一个明确的后续要求：真实应用需要验证读区、时钟和关联依据，并研究单码错误的额外核对机制；读到一个有效码并不充分。

## 3 后台调度：先验证可行区间

队列使用抽象tick：前台每10tick来一帧、占用3tick；后台每项分别消耗5、20、60tick。等待容量4，要求在入队后120tick内完成。没有把tick换算成毫秒或PYNQ帧率。

比较关闭后台、完整任务不可抢占、整项任务能放进下一空隙才启动，以及每tick可暂停/恢复的切片模型。切片模型需要真实可恢复执行路径或独立资源；给完整PyTorch调用设置低线程优先级，不会自动实现这种能力。

以下为后台代价20tick时的调度结果，前台每会话均生成120帧。任务完成只表示代价模型完成服务，不等于模型已正确识别身份。

| 输入负载 | 策略 | 按时完成任务 | 前台截止错失 |
| --- | --- | --- | --- |
| 稀疏20任务 | 关闭后台 | 0/20 | 0/120 |
| 稀疏20任务 | 不可抢占 | 20/20 | 20/120 |
| 稀疏20任务 | 完整任务须放进空隙 | 0/20 | 0/120 |
| 稀疏20任务 | 可切片 | 20/20 | 0/120 |
| 突发20任务 | 不可抢占 | 16/20 | 20/120 |
| 突发20任务 | 可切片 | 14/20 | 0/120 |
| 持续90任务 | 不可抢占 | 41/90 | 52/120 |
| 持续90任务 | 完整任务须放进空隙 | 0/90 | 0/120 |
| 持续90任务 | 可切片 | 23/90 | 0/120 |

每个前台空隙最多7tick，所以20tick的不可拆分任务永远无法放入空隙；持续90任务时，可切片方式虽保护前台，后台仍有51个容量拒绝和16个部分执行超时。突发场景中，它的按时完成数还低于不可抢占方式；这是一项前台预算优先的取舍。

将后台代价降至5tick作为正对照，持续90任务可在空隙内全部完成，前台无截止错失。这说明需要先测量真实单任务代价、最长不可抢占段、牛流和剩余服务能力，再决定架构与队列策略。

所有任务均有终态或会话结束的待完成记录。队列仿真假定视觉事件已提供，前台截止错失没有被擅自转换成实际计数召回率。后台实际模型执行没有在本轮重跑：实验适配器使用已冻结的视觉候选缓存，代价是参数扫描。
