# 仅未确认轨迹阶段使用纯IoU：固定缓存单因素控制

2026年10月30日。新旧O8只读分解发现开发参照103的新增损失：9545帧产生暂定25，9550帧原始检测0.28858；置信度融合代价≥0.7114，不能通过未确认阶段0.7门限，轨迹25被丢弃并新建26，随后只保留两次入口稳定观察。实际空间代价与决策需通过本轮插桩再确认，不仅凭理论下界宣称唯一原因。

1. 唯一干预：在`BYTETracker._unconfirmed_association`调用范围内临时关闭fuse_score，返回后立即恢复。第一关联、第二关联、检测置信度、high0.25、low0.1、new0.25、未确认代价门限0.7、区域阈值、稳定3次和入口交接保持。原类源码不改，实验使用独立子类。
2. 冻结原90条完整／裁剪缓存、旧实际O8与新FP32／QDQ／实际O8各三采样路径，以及9个历史原生来源，合计111缓存。保留原640人审12头、官方Toros6及长片person_control。原始raw不变，不运行新网络，不读最终留出像素。
3. 每一缓存先重现既定跟踪观察、ID和两条事件路径，再运行控制，输出全轨迹与所有评价窗口。CPU缓存要求严格相等；板端缓存沿用此前已冻结的0.002像素／2e-6轴坐标门限，ID、事件、键及顺序仍必须相同。此容差在新结果前写定，不能由首次差异临时放宽。
4. 记录焦点9550关联矩阵、分数融合前／后与实际选择，验证“只换这阶段代价”是否延续暂定ID、补齐入口并改变完整通行。开发640编号不是独立GT，不参与实际算法。
5. 全部111缓存、222个跟踪条件和444条计数路径独立复算，保留全部seed／负例／不利结果。原片只有12总数，不报逐事件准确率；Toros发布方6事件可正常评分，长片未接收草案不作正式成绩。
6. 完成单因素控制与自审后再决定是否进一步做实际ARM及同板O8周期验证。现有板上程序与模型不自动替换，参数门限、历史输出和所有失败记录保留。

这是开发诊断与常规ByteTrack工程对照，不是新颖性已证明的论文算法。独立事件、真实双向普通俯视和永久身份参考仍待补。
