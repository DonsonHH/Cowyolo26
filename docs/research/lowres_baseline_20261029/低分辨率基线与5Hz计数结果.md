# 192／256／320固定基线：精度、计数与5Hz采样

2026年10月29日。按用户补充的PYNQ-Z2候选尺寸完成本轮[先行计划](<计划与验收.md>)、实际推理与自审。

**现有模型不能仅靠缩小输入就同时保住当前计数效果与5Hz目标。** 本轮原片5Hz、方形输入下，三个微调seed在192只计到0／1／2，256为7／7／7，320为10／8／10；人工确认总数为12。原640成功版本保留，未作默认替换。

本轮是服务器FP32离线对照，5Hz指送入跟踪计数的采样频率，**不是PYNQ实际推理速度**。板端已取得真实环境清单，但短测PID8082的终态未能观测，尚无本次板上帧率；详情见[板卡核查与恢复关口](<../pynq_lowres_20261029/PYNQ低分辨率部署与连接核查.md>)。

## 固定范围与回归关口

保留官方YOLO26n和原seed26／27／28权重，共4模型×3尺寸。全部CW90源方向规则、置信度0.2、FP32、同一BYTETracker与两个计数器，输入统一为方形letterbox。该定义对应已有板端模型图的`1×3×S×S`；与此前矩形补边实验分开，不把所有历史差异都归为分辨率。

定位使用已审核的Cows2021开发验证1571图、1864个可见躯干外包框。原片从frame0顺序解码到10873，每5帧预测，保留历史，只评价用户指定8912–10873范围。Toros479帧全部预测一次，再从**同一检测缓存**分别取每6帧和每1帧，形成5Hz与30Hz控制。

新计数前先精确重现既有seed26原片2175个观察刻度及12头结果，以及Toros官方479个刻度和6次正确匹配；全部观察、两个计数器事件列表均一致。没有修改跟踪关联代价、稳定样本数3、最大间隔2秒或确认交接规则。

数据都已用于开发，不称新的最终未见测试。原片只有已接受的总数12，没有独立逐事件参考就不填写该片事件F1；Toros使用此前已审核的发布方轨迹导出6事件，匹配时间容差2秒。

## Toros：5Hz与30Hz的差异不能混在一起

| 模型／输入 | 5Hz TP / FP / FN | 30Hz控制 TP / FP / FN |
| --- | --- | --- |
| 官方192 | 1 / 0 / 5 | 4 / 0 / 2 |
| 官方256 | 4 / 0 / 2 | 6 / 0 / 0 |
| 官方320 | 4 / 0 / 2 | 6 / 0 / 0 |
| seed26，三个尺寸各自 | 均0 / 0 / 6 | 均0 / 0 / 6 |
| seed27，三个尺寸各自 | 均0 / 0 / 6 | 均0 / 0 / 6 |
| seed28，三个尺寸各自 | 均0 / 0 / 6 | 均0 / 0 / 6 |

官方256／320的同一检测缓存，在30Hz可以形成6次正确事件，按5Hz送入当前计数链路后为4次。该配对支持采样频率影响当前系统输出，但尚未定位具体是轨迹确认、稳定区域观察还是二者共同导致。当前稳定规则没有为5Hz重新调参，也不会直接把30Hz成绩填入5Hz验收表。

三个微调seed全部不利结果保留。这一片也仍是已用过的6事件开发诊断，不能说明真实同一通道双向已经完成。

## 执行与核查

通过[use-renly-slurm技能](<../../../ARCHIVE_CONTENTS.md#omitted>)核对账户、实时分区和作业后执行，未在登录节点运行网络计算。

第一作业130501在创建输出目录时失败，未完成源图检测；第二作业130502实际完成18852个定位图条件和26100个原片图条件后，因Toros路径指向不存在位置而失败。确认终态后仅修正源路径，SHA256、权重、参数、采样和评价保持，130503复用已完成44952条源图预测，只补5748次Toros前向，完成0:0。旧文件hash在续行前后相同，没有重跑或覆盖原片结果。

因此总实际源图检测为50700；续行predictor钩子直接计得5748。先前作业的内存钩子累计值未恢复，不伪造一份完整钩子日志，44952已有预测的来源由原执行代码、终端进度及文件对应核查。130502用时3分24秒，130503为16秒；这些是离线服务器时间。

独立脚本重新计算：18852图像匹配、20801个候选定位IoU、43119个原坐标逆变换、32808个跟踪观察刻度、5971个ROI中心、72个计数路径及48个Toros逐事件评分。事件分配有2个同最优解情形，保存评分使用的配对属于最优集合，未要求独立枚举器任意选出的第一解完全相同。

媒体作业130504完成0:0，1分12秒；三视频共5886帧严格解码通过，12个预定源帧在实际编码视频中抽取并与预览对齐核查，48图像面板均已查看。科研图第一版存在数字／图例拥挤，另存布局v2并再次核对48个实际SVG柱，数值和视频未变；当前报告只使用修正版。

## 决策与下一步

本轮不以某一尺寸、seed或恰好计数结果替换原12头成功组合，也不声称板上达到5FPS。

1. 板端恢复后先读取PID8082任务与系统日志，确认现有固件／DMA和资源状态，再从最小可观测测试恢复，避免重复提交未知状态的硬件任务。
2. 离线优先把已有固定橙框通道与整幅缩放作对照，检查在192／256／320下保留更多牛体有效像素是否改善连续检测。固定物理通道范围，不按新计数结果调宽度，不把它认作新算法贡献。
3. 再执行已改为三尺寸的[训练因素计划v2](<../../../research/detector_factorial_20261029/protocol/training_v2_lowres_plan.json>)，先短跑验证直角像素／框同步、真实梯度和更新，再安排正式训练。原640九候选未执行；新计划15个训练条件也尚未提交，不把计划写成训练成果。
4. 按已知5Hz频率诊断跟踪与稳定计数，改动要回归原12头、反向6事件和新会话，不临时放宽规则以追到目标数量。
5. 新奶牛权重需要重新量化／编译到加速运行器，验证精度和数值，再测检测＋后台身份同板负载。现有COCO部署历史与服务器采样5Hz均不能替代这个关口。
