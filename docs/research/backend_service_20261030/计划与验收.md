# 同一有界输入下的后台服务：事前计划

2026年10月30日。上一轮为实质进展：有界输入已在真实板卡重叠，吞吐提高，40身份任务与70Torch参考通过，但61–79秒后台完成和计数10／人工12仍未解决。本轮比较调度，不重训或改变计数规则。

1. 固定mosaic050_seed26、192、O8、已验证JPEG生产者、1秒过去帧选择、PNG0、同一图库及拒识阈值。四次顺序为idle_gate→low_priority_parallel→low_priority_parallel→idle_gate，每次392个5Hz时隙、78.4秒。
2. idle_gate沿用每帧SIGSTOP并waitpid确认，前台后SIGCONT。low_priority_parallel不按帧暂停，保持单线程及nice+10，由系统在两个ARM核上调度；不调整全局优先级、CPU频率或其他服务，不添加服务器推理。
3. 两组都记录子进程实际nice、亲和性、每个任务的CPU／墙钟；新增每帧边界/proc子进程stat累计utime＋stime快照。它以clock ticks计量并包含边界读取开销，不能据单个tick定位某个神经层的精确CPU重叠。新仪器两组一致，新idle才是直接基线。[Linux stat字段说明](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html)
4. 继续从0–8910真实raw恢复1783观察，启动共8真实视频准入、各次2预热。验证全部完整raw、两个计数路径、四次生产者释放／接收、实际JPEG与40上下的触发照片／输入／特征／候选。后台任务按真实触发数统计，不为了同负载补造事件。
5. 对比前台吞吐、丢弃时隙、P95／P99、200ms迟到，后台排队／完成与处理CPU；同时看计数和候选风险，不以更快后台换来更差前台后仍称全面优化。两轮同片段重复不是独立会话，跨阶段状态／校验／仪器差异另列。
6. 输入仍是192已就绪回放＋实际读取高分JPEG，启动校验读过全部JPEG可能影响内核缓存。生产线程正式时隙不读未来帧，应用层缓冲有界；真实相机曝光／编码和RFID输入仍未证明。永久ID无GT，接受预测不叫正确找回。
7. 输出全部四次、所有照片、数值参考及自审。生产者和后台进程终态、原O8／锁／服务复核前不结束设备分支。默认不因最好一轮而自动替换；人审12与独立逐事件／永久身份的缺口继续保留。
