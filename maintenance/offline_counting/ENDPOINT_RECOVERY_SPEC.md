# 端点局部补检：有界开发验证

2026-11-02。以3b2f5545发布版本为审阅基准。camera2 8月19日原片已用于失败分析，后续该片只作开发验证，不恢复为未见测试。

## 问题和机制

原始完整实机输出上行10次，用户在预测前确认11次。缺失轨迹已稳定到达起点，但终点仅有一次真实观察，未满足原有两次观察确认。四个因果单牛裁剪的板端诊断中，34.0、34.2、34.4秒可取得有效终点检测；简单扩大左侧上下文未解决问题。

候选在通用视频入口中增加可选 `endpoint_recovery`，默认关闭。仅对已有稳定起点、已首次观察到另一端、缺少当前全局检测的轨迹，用过去两次实际观察外推局部ROI，调用同一个检测器。预测框只决定在哪里再看，不能成为计数观察。

要求：

- 原图坐标、旋转和letterbox沿用同一Transform；局部ROI使用1.5倍过去框尺寸，裁到源画面，不使用未来帧、固定片名、帧号或预期数量。
- 历史最多两条观察/存活ID；只补最近1秒内轨迹，每帧最多2次，每段视频最多32次，同一端点尝试最多2次。预算耗尽继续普通检测并保留不确定记录。
- 候选须满足普通检测阈值、预测框IoU至少0.2、面积比0.25–4、物理通道内。与本帧已有通道内框的IoU必须小于0.5，且严格低于与目标预测框的IoU；邻牛归属同样好或更好时拒绝。最终仍经普通关联；不强行指定ID。全局覆盖判断和去重均用与跟踪前置过滤相同的物理准入，通道外牛不抑制补检。
- 每个源时刻只更新一次跟踪和计数；原有stable_samples=2、门线、起点、最大间隔均不放松。局部无检测、检测到邻牛或回头不能凭外推补数；已完成通行不反复补检，真实返程可重新确认。
- 记录每次局部ROI、变换、目标ID、候选及选中框。分别报告base_model_forwards、endpoint_recovery_forwards和总model_forwards；processed_frames仍是源观察时刻数。
- 原v4失败记录、源视频、人工11次参考全部保留。用户规定的展示/本次复测区间仅为原片14≤PTS<95秒；原全片599次执行不能改写成405次。

## 验证和判断

先用真实缓存＋已执行的单次局部板端检测验证机制，再做像素软件夹具（局部仍能看到/完全看不到、预算、邻牛与已完成状态），随后独立目录运行PYNQ完整81秒开发片。缓存复算不能冒充新增完整NN执行，软件夹具不能冒充奶牛精度。

至少另一个未据结果选参的较长连续视频和独立人工数量/方向参考，才支持下一轮冻结验收。仅11/11总数吻合不能推出逐事件P/R/F1、跨牧场泛化或论文就绪。
