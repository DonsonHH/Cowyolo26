# 两轴审阅与修正记录

审阅冻结点为本地提交1357e4e4（另考虑783a32db仅说明文字的澄清）。按code-review技能分别审阅Standards和Spec；以下保留两轴判断，不把一轴通过当作另一轴通过。修正与复测追加在报告之后。

## Standards

明确规范违规：未发现。仓库没有适用于改动范围的独立编码规范；以下为判断性异味，均为P2。

- 可能的Repeated Switches：review.html中的seek在两种模式下分别维护就绪状态。视频跳帧没有锁定标记操作，seeked之前可记录尚未显示的目标帧。应统一跳帧生命周期，并覆盖原生视频控件触发的seeking。
- 可能的Primitive Obsession／Shotgun Surgery：review.html写死W*.34、W*.75、[.4,.6]及纵向通道，而runner／render读取配置；水平通道或不同边界会得到错误复核引导。应由模板元数据定义通道。
- 可能的Primitive Obsession：草稿身份只有源视频hash，同视频换会话或复核区间会加载／覆盖旧事件。应包含会话、区间及通道协议，旧草稿显式校验后导入。

Standards：0项明确违规、3项判断性发现；该轴最严重后果是复核画面与记录帧号可能不一致。

## Spec

3项可修复问题，均已用纯软件夹具复现：

1. 遮挡后静默丢失不确定记录。counter超过观察间隔即清空origin；稳定A→中间→遮挡3.8秒→稳定B，事件与不确定记录均为空。违反规划“严重遮挡时，输出不确定／截断记录”。
2. 抽样未遵守源时间合同。runner按名义FPS固定帧间隔；连续VFR夹具配置5Hz，实际间隔0.5／0.125秒，并触发4次错误重置。违反规划“按选定的源时间采样”。
3. 人工复核通道写死。提供横向配置仍绘制纵向旧通道，会引导错误标注。违反规划“换视频及通道配置无需改源码”。

Spec：3项发现；该轴最严重项为不正确的源时间抽样。原片逐事件JSON、候选冻结及独立会话仍是外部验收前提；两轮12／0不能代替这些证据。未发现明显范围扩张。

## 处理与复测

| 发现 | 修正 | 证据 |
|---|---|---|
| 视频跳帧未锁定 | 所有seek先锁定，原生seeking也锁定；实际就绪及非seeking才可标记 | Node VM原始脚本红灯、修正后5项通过 |

| 遮挡间隔静默重置 | 重置前写observation_gap诊断；未完整通行的片段显式记录 | retained ID连续tick、遮挡3.8秒软件回归 |
| VFR时钟错误 | 按源PTS取样；运动和过程噪声按真实间隔推进，Lost按源秒过期；预测不作为观察 | VFR夹具、Kalman单位步一致／协方差PSD／时间过期检查 |

单元步长仍调用冻结Kalman路径。非单位时间的协方差扩展由原单位噪声推导，详见counting/source_clock.py；没有引入新训练或按原片事件特判。它是实现正确性的工程修复，不宣称论文算法创新。

非零起点默认顺序解码确认帧序；可提供同一原文件的顺序PTS索引加速，成功读取后的PTS必须等于索引中该帧的唯一时间，否则回退顺序解码。复核帧图也使用顺序解码，只有像素hash与PTS已核实的索引点可加速跳转。源时间不再由frame/FPS猜测。

原片缓存用修正后的逻辑复算仍为12次，源帧、时间、方向未变；最后一个事件的临时ID从0:48变为0:46，新增3条诊断。保留原始实机记录，不为对齐ID改写它们。当前版本另做完整实机确认，状态见STATUS。
