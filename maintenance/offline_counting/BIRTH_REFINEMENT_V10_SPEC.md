# V10：限制边缘补检，保留相机安装配置

V9R1 完整 Aug14 实测为 10/12：184 次全局、51 次起点、2 次端点、1 次热身，共 238 次模型调用。1 秒服务协议通过，计数失败。约 27 秒的原漏计已找回，但原快速通行组损失两次；不把诊断收益说成系统成功。

本次只增加起点弱框的可见范围要求：框在通行轴方向须离检测 ROI 两端边界超过该轴长度的 2%，再允许当前图局部放大。贴边、身体仍截断的候选暂缓，普通全局检测及跟踪照常运行。此条件依赖安装几何和当前框，不依赖视频名、时间、帧号或参考总数。沿用 V9R1 的单图共享一次额外调用及两次真实图像稳定要求。

Camera1 快速通行配置沿用 S256、720p5Hz 输入、5Hz 目标采样、观测速度关联、双帧缓冲，显式启用此补检；解码 .02/high .15/new .25/low .1。既有三条真实检测缓存上 high .2→.15 均未改变计数（11/12/10），这里只证明缓存关联，不能替代完整推理。

Camera2 使用此前已实测 11/11 的 normal 安装配置：同一模型和720p5Hz输入，3Hz 采样、Kalman、单帧缓冲、解码 .1/high .2，新起点补检关闭。该配置选自 Aug19 既有开发证据，不使用 Aug20 预测。统一程序根据显式配置运行，不在源码按日期/视频 ID 分支。

先软件/ARM检查，再冻结新目录并按 Aug14、Aug15、Aug19 顺序完整实测。三段分别以既有用户参考 12、12、11 检查，同时检查完整性、延迟与事件图像。开发通过才运行仍无模型推理的 Aug20 上行12参考。服务延迟边界保持既有1秒协议，失败保留，未经独立时刻GT不声称事件F1；全部结论限板上1倍墙钟视频回放，实体摄像头尚未接入。
