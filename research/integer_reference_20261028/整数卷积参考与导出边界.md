## 2. 数值实现具体改变了什么

新实现保留原seed26身份编码器结构、已冻结量化参数和全部52组INT8权重，只改变量化卷积的计算合同：

| 环节 | 新参考的明确规则 |
| --- | --- |
| 输入量化 | FP32除以原scale，nearest-even舍入，加原UINT8零点并截断到0–255 |
| 权重表示 | 既有INT8整数w用UINT8的w+128表示，权重零点为128；912008个元素逐项验证双射等价 |
| 累加 | 减零点后做精确整数点积；NumPy参考使用INT64，并检查绝对和上界不超过INT32范围 |
| ONNX执行 | 标准ConvInteger产生INT32累加，随后显式Cast为DOUBLE |
| 数值重建 | 按顺序乘DOUBLE输入scale、DOUBLE逐输出通道权重scale，加原FP32偏置转成的DOUBLE，再Cast回FP32 |
| 输出量化 | 使用原输出scale、零点和范围，显式FP32除法及nearest-even舍入 |
| 其余网络 | 激活、SE、残差及最终归一化等继续采用原FP32运算 |

整数卷积、零点和INT32输出以[ONNX ConvInteger-10定义](https://onnx.ai/onnx/operators/onnx__ConvInteger.html)为接口依据；本轮另加了不会溢出的上界检查。舍入规则参考[QuantizeLinear-13](https://onnx.ai/onnx/operators/onnx__QuantizeLinear.html#quantizelinear-13)。实际兼容性由下面的向量和逐层检查验证。

这个候选没有声称全网络都是整数，也没有实现最终的定点乘子、移位、饱和与硬件接口。DOUBLE重建是用于确定数值参考的中间方案；它在ARM或PL上的开销尚未测量。

本轮旧图的未优化参考路径先将输入和权重还原为浮点再计算Conv；新路径先做整数累加，再按明确顺序重建。两者的舍入位置可以不同。**不能用新路径通过，反向改写原QDQ路径为通过。**

## 4. 独立复算覆盖什么

主参考用NumPy的INT64窗口点积实现卷积，并先通过普通卷积、深度卷积、分组卷积、非对称padding、步长、dilation及半整数舍入控制。

独立实现不调用该窗口点积函数，而使用PyTorch FP64卷积处理已减零点的整数输入与权重。每个累加的绝对和上界均小于INT32上限，也小于FP64能精确表示整数的范围；并实际检查输出为整数、再逐元素hash对照。结果为：

- 8向量×52层，共416个整数累加条件一致，合计重算11325248个累加元素。
- 重建后的FP32卷积值、输出UINT8量化值也与主参考逐项一致。
- 关闭优化的完整ONNX图中，416个累加张量全部与主参考一致，包含上游网络可能传播的差异。
- 912008个既有INT8权重与新UINT8表示减128后完全相同；未重新训练或重新量化权重。
- 全部16个“向量×优化条件”的最终特征误差与余弦，服务器独立实现和本机NumPy复算一致。
